# 포트폴리오 리스크 카드 설계

- 작성일: 2026-08-03
- 상태: 구현 완료 (2026-08-03)
- 배경 맥락: KOSPI가 20거래일 −33% 급락 중 (2026-07-31 실측). /portfolio는
  손익·배분 비중까지만 답하고, "지금 내 포트폴리오가 견딜 수 있나"에는 무응답.

## 1. 배경

/portfolio가 현재 답하는 질문: 얼마 벌었나(손익 타일), 무엇을 들고 있나(테이블),
어디에 쏠렸나(배분·HHI·팩터 노출). 답하지 못하는 질문:

- 보유 종목들이 **얼마나 같이 움직이나** (분산이 실제로 되고 있나)
- 이 조합의 **역사적 변동성·최대낙폭**은 어느 정도였나
- **지금 같은 급락이 계속되면** 현재 비중 기준으로 얼마나 잃나

필요한 부품은 전부 있다: `module/metrics.py`(ann_volatilities·max_drawdowns·
covariance_matrix), `Backtest().data(meta_id=...)`(가격 로드 — optimization
라우터가 서빙 시점에 같은 패턴으로 사용), `datastore/fx.to_krw`(US → KRW),
holdings의 KRW 평가·비중 계산. **재조합이지 신규 엔진이 아니다.**

## 2. 목표

`GET /holdings/risk` 하나와 `/portfolio`의 `RiskCard` 하나. 현재 보유 비중을
고정했을 때의 역사적 위험 특성을 사실 그대로 보여준다.

## 3. 비목표

- **리밸런싱·축소 추천 없음** — "위험이 높다/낮다" 라벨도 붙이지 않는다.
  실측치 제시까지. 판단은 사용자 (앱 전체 원칙).
- **모수적 VaR/ES 없음** — 정규분포 가정 수치는 이 급락장에서 바로 거짓말이
  된다. 히스토리컬 윈도우만 쓴다.
- **배치 이관 없음** — 보유 ≤50종목 × 3년 일별 수익률 계산은 서브초.
  optimization 엔드포인트와 같은 서빙 시점 계산 (Lambda 전례 있음).
- **몬테카를로·스트레스 시뮬레이션 없음** — 후속 검토.

## 4. API — `GET /holdings/risk`

### 4.1 계산 정의

```
holdings 로드 (없으면 빈 payload)
→ Backtest().data(meta_id=[...]) 로 3년 조정가 로드
→ fx.to_krw(price_df, tickers_iso) 로 US 종목 KRW 환산  (holdings 평가와 동일 기준)
→ 일별 수익률 → 현재 비중(w, KRW 평가 기준 — /holdings와 동일 계산) 고정
→ 포트폴리오 수익률 r_p(t) = Σ w_i · r_i(t)   (매일 리밸런싱된 고정비중 가정)
→ 합성 NAV = Π(1 + r_p)
```

산출:

| 필드 | 정의 |
|---|---|
| `ann_vol` | r_p 연환산 변동성 (%) |
| `max_drawdown` | 합성 NAV 최대낙폭 (%) + 그 구간(from/to 날짜) |
| `avg_pair_corr` | 보유 종목 일수익 상관행렬의 비대각 평균 |
| `corr_matrix` | 종목×종목 상관 (히트맵용, ticker·name 포함) |
| `scenarios` | §4.2 히스토리컬 윈도우별 r_p 누적수익 (%) |
| `warnings` | §4.3 데이터 품질 경고 목록 |
| `basis` | `{lookback_days, n_assets, weights_as_of, window: {start, end}}` — 모든 수치의 전제를 응답에 명시 |

### 4.2 시나리오 — 히스토리컬 윈도우

"현재 비중을 이 구간에 적용했다면"이라는 반사실 가정임을 응답과 UI 문구에
명시한다 (당시 실제 보유와 무관).

| key | 구간 | 의미 |
|---|---|---|
| `recent_20d` | 최근 20거래일 | 진행 중인 급락 — 실제로 방금 겪은 구간 |
| `worst_20d` | 룩백 내 r_p 최악 20거래일 롤링 | 이 조합의 역사적 최악 한 달 |
| `worst_60d` | 룩백 내 최악 60거래일 롤링 | 최악 분기 |
| `covid_2020` | 2020-02-14 ~ 2020-03-23 (고정 상수) | 참조 위기 구간* |

*고정 위기 구간은 보유 종목 이력이 그 구간을 덮을 때만 계산하고, 아니면
`null` + 사유. 룩백은 3년(기본)이지만 고정 구간 계산 시에는 해당 구간을
포함해 로드한다 — 구간별로 커버 가능한 종목 부분집합이 아니라 **전 종목
이력이 있는 경우에만** 계산한다 (부분집합 계산은 비중 재정규화로 조용히
다른 포트폴리오가 된다).

### 4.3 데이터 품질 경고 (조용히 계산하지 않는다)

| 조건 | 경고 |
|---|---|
| US 개별주 (아카이브 2025-12 동결) | "N종목 가격 이력이 2025-12에서 멈춤 — 이후 변동 미반영" + 해당 티커. 이 종목이 있으면 `recent_20d`/`worst_*`는 계산하되 경고를 최상단에 |
| 최근 5일 거래량 0 (KR 정지) | "거래정지 의심 — 동결 가격이 변동성·상관을 과소평가" |
| 이력 < 250일 종목 | "이력 부족 — 공통 구간으로 절단됨" |
| 공통 구간 < 60일 | 위험 수치 전체 생략, 사유만 반환 |

### 4.4 계약

- holdings 비었으면 `{empty: true}` — 500 금지.
- 단일 종목 보유: 상관 생략(`corr_matrix: null`), 나머지는 계산.
- 가격 조회 실패 종목: holdings 페이지와 동일하게 제외 + 경고.

## 5. 프론트 — `RiskCard`

`/portfolio`의 AllocationCard와 FactorExposureCard 사이. 페이지 내 카드이므로
스포트라이트 레인과 달리 **로딩 스켈레톤·에러 상태를 렌더한다**
(LoadingState/ErrorState 기존 컴포넌트 — 개인 핵심 페이지 관례).

```
┌ 위험 요약 ──────────────────────────────────────┐
│ [연변동성 24.3%] [최대낙폭 −31% (22.01~22.09)] [평균상관 0.62] │
│                                                  │
│ 시나리오 (현재 비중 가정)                          │
│  최근 20일          −18.2%   ← 진행 중            │
│  역사적 최악 20일    −24.1%  (2020-03)            │
│  역사적 최악 60일    −33.7%  (2022-01~03)         │
│  코로나 급락 재현     −28.9%                       │
│                                                  │
│ 상관 히트맵 (보유 종목 √)                          │
│  ⚠ 미국 개별주 2종목 이력 2025-12 동결             │
└──────────────────────────────────────────────────┘
```

- 평균상관 타일에 InfoTip: "1에 가까울수록 같이 움직임 — 분산 효과 없음"
  (사실 설명, 판단 아님).
- 히트맵은 optimization CorrelationSection의 렌더링을 참조하되 읽기 전용
  소형으로 새로 만든다 (그쪽은 페어 선택·롤링 차트가 붙은 무거운 화면).
- 값 색상은 기존 토큰(var(--gains)/var(--losses)) — 새 디자인 언어 없음.

## 6. 에러 처리

| 계층 | 처리 |
|---|---|
| API | 부분 실패(일부 종목 가격 없음) → 경고와 함께 진행. 전체 실패 → 500 아닌 `{empty: true, reason}` |
| 프론트 | 로딩 스켈레톤, 에러 시 ErrorState, empty 시 카드 미렌더 |

## 7. 테스트

| 대상 | 방식 |
|---|---|
| 시나리오 윈도우 계산 | 순수 함수 분리 + 픽스처 — worst_20d가 실제 최악 구간을 찾는지, 고정 구간 부분 커버 시 null인지 (TDD) |
| 고정비중 포트 수익률·MDD | 픽스처 — 손계산 대조 (2종목 50:50, 알려진 수익률) |
| API 계약 | 빈 보유 → `{empty: true}`, 단일 종목 → corr null (monkeypatch, spotlight API 테스트 패턴) |
| KRW 환산 | US 종목 포함 픽스처 — fx 적용 여부가 vol에 반영되는지 |

계산 로직은 `server/module/portfolio_risk.py`로 분리한다 (라우터는 얇게 —
spotlight 모듈과 같은 구조).

## 8. 비용

- Lambda: 요청 시 ≤50종목 × ~750일 로드·계산 — optimization과 동급 (서브초).

## 10. 한계 (응답·문서에 명시)

- 고정비중 가정은 실제 보유 경로와 다르다 (매일 리밸런싱 가정) — 정확한
  과거 실적이 아니라 "이 조합"의 특성이다.
- US 개별주 동결 이력은 최근 위험을 과소평가한다 — 경고로만 대응 (ETL
  재개는 별건).
- 히스토리컬 시나리오는 과거가 반복된다는 가정이 아니다 — 참조점 제시일 뿐.

## 12. 구현 중 확인 (2026-08-03)

- **가중 불가 자산의 처리 정정**: §4.3은 US 동결 개별주를 "계산 포함 + stale
  경고"로 적었으나, 30일 내 시세가 없는 자산은 현재 비중 자체를 정직하게 계산할
  수 없다 (모든 수치의 뿌리가 비중이다). 구현은 이런 자산을 `no_price` 경고와
  함께 제외한다 — 조용한 제외가 아니므로 원칙 위반이 아니다. `stale` 분기는
  시세는 있으나 가격 이력이 패널 대비 7일 이상 뒤처지는 자산용으로 남는다.
- **US 아카이브 동결의 범위**: 2025-12 동결은 개별주만이 아니라 레이크에 등록되지
  않은 US ETF에도 해당한다.
- **실데이터 검증**: 운영 holdings가 비어 있어(0행) 경로 검증은 실제 meta_id
  4종(KR 3 + US 동결 1) 인프로세스 픽스처 + 실제 S3 가격 이력으로 수행했다.
  ann_vol 40.0%, MDD −47.5% (2026-06-22~07-30), recent_20d −15.2% — 원자료
  가중평균과 일치 확인. 실보유 입력 전까지 카드는 렌더되지 않는다 (정상).
