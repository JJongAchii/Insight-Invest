# US 가격 소스 일원화 — qdata massive 미러 단일화

- 작성일: 2026-08-04
- 상태: 설계
- 사용자 방향: yfinance 를 완전히 걷어내고, US 가격을 qdata massive 기반
  clean 데이터로 일관되게 사용한다. 1993~2003 아카이브 이력은 포기한다
  (2003-09 플로어 수용 — 사용자 결정).

## 0. 배경 — 왜 지금인가

활성 전략(port 1)의 유니버스 6종목 중 XLE·TMF 가 동결 아카이브(2025-12-12)에
묶여 **리밸런싱이 2025-12-01 이후 8개월간 멈췄고 리밸 신호도 영원히 발화하지
않는 상태**다 (2026-08-04 실측). yfinance 16종 ETF 테이블 + 동결 아카이브의
이원 소스가 원인이며, massive 일일 수집·발행이 완료된 지금이 단일화 시점이다.

## 1.5 정합성 검증 (2026-08-04 실측 — yfinance 대조, ETF 10종 + 개별주 14종)

XOM·JPM·MO·GOOGL·AMZN·META·C·GE·T·MMM·BRK.B).

## 2. 결정

### D1. US 가격의 단일 소스 = massive 미러, yfinance 완전 제거

`datastore/prices.py` 의 US fresh(yfinance 16종)/stale(동결 아카이브) 이원
분기를 제거하고, 배치가 재생성하는 앱 플레인 `us_prices.parquet` 하나만 읽는다.
qdata `prices.parquet`(yfinance) 의존과 `_qdata_us_tickers()` 가 사라진다.

### D2. Lambda 는 2.77GB 미러를 직접 읽지 않는다 — 배치 추출 유지

미러는 date 정렬이라 티커 필터로 row group 이 잘리지 않는다. 23년 범위 요청은
수백 MB 스캔이 되어 Lambda 2048MB/응답시간 계약을 깬다. 기존 아키텍처
(배치 = 무거운 계산, Lambda = 가벼운 서빙) 그대로: **야간 배치가 meta 에 등록된
US 티커만 추출해 앱 parquet 를 재생성**하고 Lambda 는 지금의 아카이브 경로
코드로 그 파일을 읽는다. 스키마 불변:
`[meta_id, trade_date, ticker, adj_close, gross_return]`.

### D3. 총수익(TR) 합성 — 기존 앱 수치와의 정합 유지

배치 추출 시 합성한다 (ADR-0007 이 정한 소비자 책임 경로):

```
F_t        = adj_close_t / close_t                  # 그날의 분할 누적계수
div_adj_t  = Σ cash_amount(ticker, ex_date=t) × F_t # 당시 주수 기준 → 분할 정규화
r_t        = (adj_close_t + div_adj_t) / adj_close_{t-1} − 1   # 단순수익률
gross_return_t = r_t                                 # 기존 컬럼 의미(단순수익률) 유지
adj_close_t(TR) = 최신일 close 앵커로 r_t 를 역누적한 총수익 계열
```

같은 (ticker, ex_date) 복수 행(특별배당)은 합산한다. 시계열 첫 행의
gross_return 은 NaN (기존 pct_change 관례와 동일).

### D4. 과거 이력은 2008-01-02 플로어 수용

원안은 2003-09(가격 축 시작)였으나, 검증(§1.5)에서 배당 축이 2007 중반부터만
신뢰 가능함이 확인돼 **배당까지 온전한 2008-01-02 로 플로어를 올린다**.
2008 이전 이력(동결 아카이브 전용)은 병합하지 않는다 — 현 소비자
(포트 백테스트 2010~, 라이브 트래킹 2024~)는 무영향. 필요해지면 그때
아카이브에서 1회 병합한다. `us_prices.parquet` 아카이브 파일은 배치가
새 산출물로 **덮어쓴다** — 경로·이름이 같아 Lambda 코드 무변경.

### D5. 티커 세그먼트 스티칭 + 연속성 가드

- 빌더 상수는 날짜 경계 세그먼트다 — 단순 합집합은 META 처럼 같은 티커에
  **다른 회사**가 살았던 구간을 함께 끌고 온다 (§1.5-1):

```python
TICKER_SEGMENTS = {  # 현행 티커: [(소스 티커, 시작, 끝)], None = 무제한
    "QQQ": [("QQQ", None, "2004-11-30"), ("QQQQ", "2004-12-01", "2011-03-22"),
            ("QQQ", "2011-03-23", None)],
}
```

  가격·배당 모두 세그먼트로 잘라 이어붙인다 (겹침 금지 검증 포함).
- **연속성 가드**: 티커별로 (a) 시계열 내부 공백 > 10거래일, (b) 분할 계수
  변동 없는 날의 |일수익| > 25% 를 감지하면 해당 티커를 경고와 함께 제외한다
  — 티커 재배정·구멍이 조용히 백테스트에 스며드는 것 차단.
  가드에 걸린 티커는 빌드 로그에 사유와 함께 남는다. 한계: T 2022 WBD
  스핀오프(-18.7%)처럼 임계 아래의 거짓 급락은 못 잡는다 → §6 온보딩 규칙이
  보완한다

## 3. 배치 신설 — `build_us_prices` (P0, 다른 빌더보다 먼저)

1. meta 에서 `iso_code == "US"` 티커 전량 조회 (수십~수백 개 수준)
2. 미러에서 그 티커들(+D5 별칭)의 close·adj_close 를 2008-01-02 부터 읽고
   us_dividends 를 조인한다 (연 단위 date 청크로 나눠 읽어 메모리 상한 유지 —
   date 필터는 row group 을 자른다)
3. D5 스티칭·연속성 가드 → D3 합성 → 앱 `us_prices.parquet` 재생성
4. **meta 등록 티커가 미러에 없으면 경고 로그 + 해당 티커 제외** (조용한 소실
   금지). 미러 접근 실패 시 기존 파일 유지 + 경고 — 하류 빌더는 어제 데이터로
   진행 (500 금지의 배치판)

기존 빌더(P1~P7: 신호·스포트라이트·트래킹·리밸신호)는 무변경 — 전부
`read_price_data` 를 통해 새 파일을 읽게 된다.

## 5. 타이밍 계약 + 강등

**계약**: 매 평일 19:00 KST 이전에 미러 `us_prices` 가 직전 마감 US 세션을
포함해야 한다. (현 수집이 오후 사이클로 자리잡았는지 오늘 실측 확인 — 미충족
시 quant-data 쪽 cron 시각 보정, 이 레포 범위 밖 선행 작업)

**강등**: 배치 시점에 미러 최종일이 기대보다 낡으면 — 앱 parquet 는 그대로
재생성(있는 데까지), 경고 로그. 리밸 신호는 `is_new_period(as_of, ...)` 검사가
자연히 스킵하므로 사후 신호가 나가지 않는다 (낡은 신호보다 무신호가 낫다).

## 6. 엣지

- **거래정지/휴장**: massive 는 거래된 종목만 일별 스냅샷에 존재 → 결측일은
  NaN 유지, 엔진(calculate_nav 구간 절단·dropna 관례)이 기존대로 처리
- **개별주 온보딩 규칙**: US 개별주를 meta 에 추가할 때는
  `scripts/validate_us_adj.py` 에 그 티커를 넣어 1회 대조를 통과해야 한다 —
  티커 재배정(META·T 개명)과 스핀오프 미조정(MO -70% 거짓 급락)은 이
  스크립트가 전부 검출했고, 자동 가드(D5)만으로는 다 못 잡는다 (§1.5).
  ETF 는 스핀오프·재배정 위험이 사실상 없어 규칙 밖
- **첫 실행 전환**: 기존 아카이브 대비 값이 달라진다 — yfinance↔massive 벤더
  차이(소폭) + XLE·TMF 부활로 라이브 트래킹이 2026-01~08 리밸 8회를 소급 반영
  (live NAV·보유 비중 재작성, 사용자 고지 완료)

## 7. 테스트

- TR 합성 손계산 픽스처: 분할+배당 동시 발생일, 특별배당 합산, 첫 행 NaN
- 별칭 스티칭: 겹침 금지·경계 연속성 픽스처, 연속성 가드 (공백·점프 감지)
- 추출 빌더: 미러 부재 티커 경고·제외, 미러 접근 실패 시 기존 파일 유지
- prices.py: US 단일 경로 계약 (meta_id 매핑·정렬·스키마), fresh-set 제거 회귀
- 신선도 강등: 낡은 미러 → 신호 무발화 (사후 신호 금지)
- 전환 검증: §1.5 로 사전 수행 완료 (yfinance 대조 ETF 10 + 개별주 14).
  구현 시 **meta 의 US 전 종목**으로 스윕을 1회 확장 실행 — 재배정·스핀오프
  피해 종목을 전환 전에 전수 색출하고, 걸린 종목은 세그먼트 등록 또는 경고와
  함께 제외를 사람이 정한다
