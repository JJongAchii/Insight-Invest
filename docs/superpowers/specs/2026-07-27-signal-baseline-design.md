# 신호 기준선 도입 + attention 표현 교정 설계

- 작성일: 2026-07-27
- 상태: 설계 확정, 구현 대기

## 1. 배경

`signal_study.parquet`은 수급 신호 3종의 전방 초과수익을 계산한다. 그런데
초과수익을 **시총가중 KOSPI 대비**로 재고 있어 두 가지 문제가 있다.

1. **KOSDAQ 종목을 KOSPI 지수에 대고 잰다** — 유니버스와 벤치마크가 다르다.
2. **기준선이 없다.** KOSPI는 소수 대형주가 끌기 때문에 중앙값 종목은 구조적으로
   지수를 못 따라간다. 그래서 모든 신호가 음수로 나오고, 읽는 사람은 "이 신호는
   나쁘다"로 해석한다.

2번은 가정이 아니라 실제로 일어난 일이다. 이 설계를 논의하는 과정에서
`bull_divergence`의 20일 중앙값 −2.28%를 보고 "이 신호는 마이너스"라고 결론지었다가,
기준선을 재보고 나서야 그게 벤치마크 산물임을 알았다. 테이블이 그렇게 읽히도록
만들어져 있다.

프론트에도 같은 문제가 이미 배포돼 있다. `SignalsSection.tsx:72`가
`median_excess < 0`을 경고 조건으로 쓰는데, 기준선이 −1.8%라 **세 신호 전부 항상
경고가 뜬다.** 항상 켜지는 경고는 정보가 없고, 셋 중 유일하게 우위가 있는
`frgn_streak10`까지 깎아내린다.

### 1.1 측정 결과

벤치마크를 **유동성 유니버스(시총≥100억) 동일가중 횡단면 평균**으로 바꿔
2016-01-04 ~ 2026-07-20, 600만 종목-일을 재측정했다.

**기준선** (신호 조건 없이 전체)

| 지평선 | 중앙값 초과수익 | 승률 |
|---|---|---|
| 5일 | −0.67% | 42.9% |
| 20일 | −1.80% | 41.2% |
| 60일 | −3.83% | 39.6% |

중앙값이 음수인 것은 벤치마크가 *평균*이고 수익률 분포가 우편향이기 때문이다.
비교는 `vs 기준선` 열로 한다.

**기존 3개 신호** (20일, 기준선 대비)

| 신호 | vs 기준선 | 판정 |
|---|---|---|
| `frgn_streak10` | +0.51%p | 약하지만 플러스 |
| `bull_divergence` | −0.29%p | 우위 없음 |
| `high_intensity` | −0.96%p | 역방향 |

**급등 조건** — 모두 세 지평선에서 일관되게 음수, 강도에 비례

| 조건 | N | 20일 vs기준 | 60일 vs기준 | 20일 승률 vs기준 |
|---|---|---|---|---|
| 1일 +5% 이상 | 276,018 | −2.39%p | −4.60%p | −3.1%p |
| 1일 +10% 이상 | 73,207 | −5.41%p | −9.16%p | −6.7%p |
| 5일 +15% 이상 | 194,345 | −4.43%p | −8.12%p | −5.5%p |
| 20일 +20% 이상 | 423,736 | −3.32%p | −6.43%p | −4.4%p |
| 20일 +50% 이상 | 85,500 | −6.36%p | −12.64%p | −5.8%p |

**대조군**

| 조건 | N | 20일 vs기준 | 60일 vs기준 | 비고 |
|---|---|---|---|---|
| 1일 −5% 이하 | 223,663 | −1.22%p | −2.95%p | 급등보다 **덜** 나쁨. 5일 승률은 +1.8%p |
| 52주 신고가 2% 이내 | 282,143 | **+0.54%p** | **+0.94%p** | 유일한 플러스, 승률 +3.0%p. N은 근접 상태 유지 전체 일수 기준 — 빌더는 상태형으로 분류해 crossing+cooldown으로 진입일만 세므로(N≈27,381), 실측 결과는 중앙값 마이너스·승률 플러스인 별도 분포다 |

마지막 행이 중요하다. **"고점 근처"와 "급등"은 정반대다.** 꾸준히 올라 신고가에
있는 것은 플러스, 급하게 튄 것은 마이너스다. 현재 앱은 이 둘을 구분하지 않는다.

### 1.2 그래서 지금 화면이 거꾸로다

`attention.py`는 1일 ±5% 급변을 이렇게 표시한다.

```python
"title": f"오늘 {chg:+.1f}% ({'관심' if up else '주의'})"
"detail": f"{'급등' if up else '급락'} {chg:+.1f}% — {'관심' if up else '주의'} 종목"
```

급등에 **"관심"**, 급락에 **"주의"** 를 붙인다. 측정 결과는 그 반대다 —
급등 뒤 20일이 급락 뒤보다 2배 나빴다.

## 2. 목표

1. `signal_study`에 **기준선을 넣어** 숫자가 오독되지 않게 한다.
2. 벤치마크를 유니버스와 일치시킨다.
3. `attention`에서 **가치판단 라벨을 걷어내고 실측치를 붙인다.**
4. 급등을 강도에 비례해 표시한다.

## 3. 비목표

- **매매 추천을 만들지 않는다.** "피하라"도 추천이다. 실측치 제시까지만 한다.
- **양의 신호(저변동·소형·저평가) 추가** — 측정에서 상위였으나 서로 겹치는
  종목군일 가능성을 아직 안 갈랐고, 거래비용·체결 문제가 남아 있다. 별건.
- **`high_intensity` 신호 제거** — 역방향이지만 지우면 정보가 사라진다.
  표시하되 실측치를 병기한다.
- **severity 체계 재설계** — 급등 강도 반영만 하고 전면 재설계는 하지 않는다.

## 4. 변경 1 — `build_signal_study()` 확장

### 4.1 벤치마크 교체

```python
# 현재
K = _kospi_close(P.index)                     # 시총가중 KOSPI
excess = fwd_ret - kospi_ret

# 변경
bench = np.nanmean(np.where(liquid, fwd, np.nan), axis=1, keepdims=True)
excess = fwd - bench                          # 유동성 유니버스 동일가중 횡단면
```

`_kospi_close()`는 다른 곳에서 쓰지 않으므로 함께 제거한다.

### 4.2 신호 추가

기존 3개에 더해 8종. 세 번째 열이 이번 설계에서 가장 중요한 결정이다.

| signal_type | 조건 (adj_close 기준) | 이벤트 처리 |
|---|---|---|
| `baseline` | 없음 — liquid 전 종목-일 | 없음 |
| `spike_1d_5` | `chg_pct >= 5` | 없음 |
| `spike_1d_10` | `chg_pct >= 10` | 없음 |
| `drop_1d_5` | `chg_pct <= -5` | 없음 |
| `spike_5d_15` | `ret_5d >= 15` | crossing + cooldown |
| `spike_20d_20` | `ret_20d >= 20` | crossing + cooldown |
| `spike_20d_50` | `ret_20d >= 50` | crossing + cooldown |
| `near_52w_high` | `adj_close >= 252일 rolling max × 0.98` | crossing + cooldown |

**1일 조건에는 crossing/cooldown을 적용하지 않는다.** 기존 3개 신호는
`streak >= 10` 처럼 한 번 참이 되면 여러 날 유지되는 *상태*라, `crossing`으로
첫날만 잡고 `_event_cooldown(20일)`로 재발화를 걸러야 한 사건이 20번 세어지지
않는다. 반면 `chg_pct >= 5`는 그 자체로 하루짜리 사건이다. crossing은 거의
무의미하고(연속 급등일은 드물다), cooldown은 **서로 다른 진짜 급등을 임의로
버린다.** 5일·20일 누적 조건과 52주 신고가는 다시 상태이므로 기존 처리를 따른다.

이 결과로 1일 급등 신호의 값은 §1.1 사전 측정치와 **정확히 일치해야 한다.**
attention 변경을 떠받치는 숫자가 바로 이것들이라 검증에 유리하다.

`baseline`에 cooldown을 적용하지 않는 이유도 같이 코드 주석에 남긴다 — 나중에
"왜 baseline만 N이 압도적인가"를 다시 묻지 않도록.

**N은 신호 간 비교 가능하지 않다.** cooldown을 적용한 신호와 아닌 신호가 섞이기
때문이다. 중앙값·승률만 비교한다. 이 경고를 컬럼이 아니라 문서와 주석에 남긴다.

스키마는 그대로(`signal_type, horizon, n_events, mean_excess, median_excess,
hit_rate, avg_fwd_ret, as_of`)이고 행만 9 → 33으로 늘어난다. **기존 소비자는
안 깨진다.**

### 4.3 필요한 데이터가 지금 버려지고 있다

`build_signal_study()`는 `chg_pct`를 로드한 직후 버린다.

```python
px = qdata_api.load_krx_prices(columns=["adj_close", "close", "chg_pct", "mktcap"])
px = px[["date", "ticker", "adj_close", "mktcap"]]  # close/chg_pct 미사용 — 즉시 폐기
```

1일 급등/급락 조건에 `chg_pct`가 필요하므로 유지한다. `close`는 계속 불필요하다.

`liquid`와 `Pv`도 마찬가지다. 현재 `del liquid, M` → `del P` 순으로 즉시 해제하는데,
기준선과 새 벤치마크가 둘 다 전체 패널의 `liquid` 마스크를 요구하므로 numpy 배열로
유지해야 한다. 실측 피크는 빌더 프로세스 전체 RSS 기준 ≈2.6~2.8GB — 지평선
루프마다 `fwd` + `np.where` 임시본 + `exc` + 마스크 추출 + `median`/`nanmean`의
numpy 내부 복사본이 ≈300MB 순간적으로 잡히고, 새로 들고 있는 영구 패널이
+~170MB, 여기에 모듈 레벨 flows 캐시 ~1.05GB가 얹힌다. 배치 EC2(t4g.large,
8GB)에서 여유 있게 돌아간다.

### 4.4 측정값이 바뀐다는 점

벤치마크가 바뀌므로 기존 3개 신호의 숫자도 전부 바뀐다. 이건 의도된 것이다.
프론트가 값을 하드코딩한 곳이 없는지 확인한다.

## 5. 변경 2 — `attention.py`

### 5.1 가치판단 라벨 제거

```diff
- "title": f"오늘 {chg:+.1f}% ({'관심' if up else '주의'})"
- "detail": f"{'급등' if up else '급락'} {chg:+.1f}% — {'관심' if up else '주의'} 종목"
+ "title": f"오늘 {chg:+.1f}% {'급등' if up else '급락'}"
+ "detail": <실측치 문장>
```

`detail`은 `signal_study`에서 해당 조건의 행을 읽어 만든다.

> 과거 27.6만건 · 20일 뒤 기준선 대비 −2.4%p (승률 −3.1%p)

`signal_study`를 못 읽으면 실측치 없이 등락률만 표시한다 — attention은 절대 500을
내지 않는다는 기존 계약을 유지한다.

### 5.2 급등 강도를 severity에 반영

| 조건 | 현재 | 변경 |
|---|---|---|
| 1일 +10% 이상 | medium | **high** |
| 1일 +5~10% | medium | medium |
| 1일 −5% 이하 | medium | medium |

+10%는 60일 −9.16%p다. 보유 종목이라면 실제로 봐야 할 수준이라 `high`로 올린다.
급락은 급등보다 덜 나쁘므로 올리지 않는다.

## 7. 검증

| 대상 | 기대 | 근거 |
|---|---|---|
| `baseline` | 중앙값 −0.67 / −1.80 / −3.83, 승률 42.9 / 41.2 / 39.6 | §1.1과 **정확히 일치** |
| `spike_1d_5` | 기준선 대비 −1.16 / −2.39 / −4.60%p, N ≈ 27.6만(20일) | cooldown 없음 → **정확히 일치** |
| `spike_1d_10` | 기준선 대비 −2.54 / −5.41 / −9.16%p | 동일 |
| `drop_1d_5` | 기준선 대비 −0.20 / −1.22 / −2.95%p | 동일 |
| 상태형 신호 5종 | 부호와 대략의 크기만 일치, **N은 크게 작아짐** | crossing + cooldown 적용 → 불일치가 정상 |
| 스키마 | 컬럼 불변, 행 9 → 33 | |
| attention | `signal_study` 부재 시에도 200 응답 | |
| 프론트 | `baseline` 행 없는 parquet으로도 렌더 | |

1일 신호 3종이 사전 측정치와 어긋나면 구현이 틀린 것이다 — 이 세 줄이 실질적인
회귀 테스트다. 상태형 5종은 cooldown 때문에 값이 달라지는 게 정상이므로 부호만
확인하고, 어긋나면 그때 원인을 판단한다.

순수 함수인 **실측치 문장 생성**과 **경고 조건 판정**은 단위 테스트를 쓴다.
빌더 자체는 전 종목 패널을 도는 계산이라 단위 테스트 대신 위 대조표로 검증한다.

## 9. 한계 (문서에 남긴다)

- **거래비용·슬리피지 미반영.** 20일 ±1%p는 왕복 비용에 상당 부분 먹힌다.
  "피하라"는 매매를 안 하는 것이라 이 문제에서 자유롭지만, 양의 신호를 나중에
  추가할 때는 반드시 반영해야 한다.
- **N은 독립 표본 수가 아니다.** 이벤트가 겹친다. 신호 간 비교는 같은 방식으로
  재므로 공정하지만 N을 유의성 근거로 쓰면 안 된다.
- **레짐 조건부 분석 없음.** 전 기간 단일 통계다. 2016~2026 안에서 국면별로
  달랐을 수 있다.
- **생존 편향 확인 안 됨.** `krx_prices`가 상폐 종목을 포함한다고 알고 있으나
  이번 측정에서 별도 검증하지 않았다.
