# 판단 워크벤치·Massive 일일 가격 운영 반영

- 작성일: 2026-08-18
- 범위: 홈 판단 요약, 데이터 상태, 목표 비중 괴리, 레짐 관측일, US SEC 재무,
  Massive 가격 배치 복구

## 반영 순서

1. `quant-data` 변경을 먼저 병합한다. EC2 수집기가 `qdata us rebuild --only ...`를
   인식해야 한다.
2. `Insight-Invest` 서버·클라이언트 변경을 병합한다. 서버 배포 후 `/overview`와
   `/stock/{meta_id}/fundamentals`를 확인하고, Vercel 프론트를 반영한다.
3. 다음 평일 09:00 또는 19:00 KST 수집 회차에서 새 `run_pipeline.sh`가 pull되면
   자체 재실행한다. `clean/us_dividends.parquet`를 raw에서 복구하고 미국 앱 가격을
   필수 모드로 재생성한다.
4. systemd 회차 성공과 로그의 최종 `OK=1`, `app/us_prices.parquet`의 최근 수정일, 그리고
   `app/data_status.parquet`의 `us_prices.status=ok`/직전 완결 세션 `as_of`를 함께
   확인한다. 셋 중 하나라도 다르면 성공으로 판정하지 않는다.

운영 데이터를 수동으로 덮어쓰는 절차는 두지 않는다. 배치의 동일 코드 경로로
자가복구해야 다음 서버 교체 때도 재현된다.

## 화면 판단 계약

- 홈은 레짐·위험 게이지·KR 시장폭·외국인 5일 수급의 방향 일치 여부를 요약한다.
  매수/매도 문장이 아니라 근거별 기준일과 충돌을 보여준다.
- 데이터 상태는 배치 sidecar를 읽는다. 큰 parquet에서 요청마다 최종일을 다시
  계산하지 않는다.
- 목표 비중은 현금을 제외한 투자자산 내 선택값이다. 목표가 없는 종목에는 주문
  제안을 만들지 않는다.
- 위험 게이지는 구성요소별 관측일을 표시하고, 종합 기준일은 가장 느린 구성요소의
  날짜다.
- US 재무는 Massive의 현재 빈티지 ticker→CIK와 SEC `filed <= today` 사실만 사용한다.
  과거 백테스트용 재무 패널이 아니다.

## 정확하게 남겨 둔 후속

다음 항목은 UI만 먼저 만들거나 최신값으로 소급 채우지 않는다.

1. **진짜 매크로 빈티지 국면**: 현재 역사 국면은 발표 1개월 시차를 적용했지만
   최신 CLI/CPI 빈티지로 재구성된다. 당시 실시간 판정을 복원하려면 ALFRED 같은
   vintage source와 충분히 누적된 OECD 스냅샷이 필요하다. 화면에 이 한계를 표시한다.
2. **현금·입출금·세금·체결 원장**: 현재 holdings는 스냅샷이므로 시간가중 실제 성과나
   정확한 주문 수량을 만들 수 없다. 원장을 도입할 때 cash balance, transaction,
   external flow를 별도 불변 이벤트로 설계한다.
3. **Decision Journal**: 판단 당시 근거와 이후 결과를 연결하려면 사용자 메모뿐 아니라
   당시 데이터 status/as_of 스냅샷을 함께 저장해야 한다. 단순 텍스트 메모만 먼저
   붙이지 않는다.
4. **뉴스의 자산 영향 판정**: 제목 감성만으로 매매 신호를 만들지 않는다. 기업·국가·
   금리·원자재 노출 매핑과 발생시각 이후 수익의 검증 설계가 준비될 때 별도 도입한다.
