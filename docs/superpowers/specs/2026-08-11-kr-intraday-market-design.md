# KR 장중 마켓 대시보드 + US 종가 아침 반영 설계

- 작성일: 2026-08-11
- 상태: 구현 완료·프로덕션 가동 (2026-08-11, §12)
- 선행: `2026-08-04-us-price-source-unification-design.md` (정산 평면 불변식,
  8/4 장중 부분 봉 사고), `2026-07-31-market-spotlight-design.md` (홈 레인 구조)

## 1. 배경

앱의 모든 데이터가 19:00 KST 일배치다. 장중(09:00~15:30)에 접속하면 어제 데이터만
보이고, "지금 장이 어떻게 움직이는가"를 파악할 수단이 없다. 사용자 요구는 명확하다:
**전반적인 장의 흐름과 현황(시세·섹터·자금·내 종목)을 장중에 파악할 수 있어야 한다.**

2026-08-11 11:11 KST 장중 실측으로 재료를 확인했다:

- pykrx(data.krx.co.kr — 야간 수집과 동일 엔드포인트·동일 AWS 접근 경로)는 장중에
  **지연(~20분) 스냅샷**을 반환한다. 전종목 시세(등락률·거래대금·시총 포함)가
  시장당 1호출, 45초 간격 재조회에서 거래량이 갱신됨(정적 값 아님)을 확인.
- 지수(1001/2001)도 당일 장중 OHLC가 나온다 (KOSPI 6,346.54 실측).
- 업종 매핑(`qdata/clean/krx_sector.parquet`, 26업종)과 전일 지수 종가
  (`qdata/clean/krx_index_prices.parquet`)는 S3 미러에 매일 갱신 중.

제약은 8/4 사고의 교훈 그대로다: **장중 값이 정산 평면(레이크·백테스트·전략 추적)에
한 방울이라도 섞이면 안 된다.** 이 설계의 모든 결정은 이 분리를 전제로 한다.

## 2. 목표

1. 장중 30분 단위로 KR 시장 현황을 수집해 인사이트 페이지 "장중" 탭과 홈에 노출:
   지수·브레드스, 섹터 히트맵, 섹터 흐름(당일 시계열), 거래대금·급등락 순위,
   내 종목(관심·보유) 장중 현황.
2. US 종가를 저녁이 아니라 **한국 아침에** 반영 (아침 EC2 기동 1회 추가).
3. 레이크·raw 체크포인트·백테스트·전략 추적 **완전 무접촉**.

## 3. 비목표

- 실시간(초·분 단위) 스트리밍 — 30분 폴링, ~20분 지연 시세로 충분하다고 합의.
- US 장중 시세 — 한국 밤 시간대라 실익 낮음. 필요해지면 Massive 티어 인상 별도 검토.
- 장중 데이터의 **분석·신호·백테스트 활용** — 표시 전용. 영구 금지에 가까운 비목표.
- 장중 히스토리 보존 — 당일만. 익일 첫 폴에서 리셋.
- KIS 등 신규 벤더 — KRX 소스만 사용.

## 4. D1 — 수집: 폴러 Lambda

서버는 ECR Docker 이미지 배포이므로 **같은 이미지에 pykrx를 추가**하고, 별도
핸들러 entrypoint(`intraday_handler.run`)로 **두 번째 Lambda 함수**를 만든다.
서빙 함수와 코드·이미지를 공유하되 역할이 다르다(폴러는 `app/` 쓰기 권한 필요).

- **스케줄**: EventBridge `cron(5,35 0-6 ? * MON-FRI *)` UTC → 09:05~15:35 KST
  30분 간격 14회. 15:35 마지막 폴이 마감치(15:30)를 캡처한다.
- **폴 1회 = KRX 4호출**: KOSPI·KOSDAQ 전종목 OHLCV + 지수 1001·2001 당일 OHLC.
  하루 56호출, 기존 THROTTLE(0.5s)·재시도 어댑터 재사용. 야간 수집과 같은
  엔드포인트라 신규 의존성·신규 차단 리스크 없음.
- **자격증명**: KRX_ID/KRX_PW를 폴러 Lambda env로 (EC2 .env와 동일 값).
- **휴장 판정**: 지수 조회 결과에 오늘 날짜 행이 없으면 휴장 — no-op 종료.
  전종목 조회가 비거나 예외면 파일 미갱신(직전 상태 유지) 후 로그만 남긴다.
  서빙의 스테일 가드가 자동으로 강등하므로 폴러는 죽어도 사이트는 멀쩡하다.

## 5. D2 — 데이터 계약 (앱 평면 파일 2개, 레이크 무변경)

둘 다 `s3://insight-invest-datalake/app/` (기존 `storage.py` 헬퍼 사용):

**`kr_intraday_latest.parquet`** — 전종목 최신 스냅샷 (~2,700행, 폴마다 덮어씀):

| 컬럼 | 내용 |
|---|---|
| ticker, market | 종목코드, KOSPI/KOSDAQ |
| open, high, low, close | 당일 장중 OHLC (close=현재가, 무수정) |
| chg_pct | **KRX 제공 등락률 그대로** (자체 계산 금지 — 락 조정 정합성) |
| value, volume, cap | 당일 누적 거래대금·거래량, 시가총액 |
| as_of, trade_date | 폴 시각(KST), 거래일 |

**`kr_intraday_timeline.parquet`** — 당일 폴별 집계 시계열 (~400행/일, append):

| kind | key | 값 컬럼 |
|---|---|---|
| index | KOSPI·KOSDAQ | level, chg_pct (전일 종가는 미러 `krx_index_prices` 최신 행 대비) |
| breadth | ALL | advancers, decliners, unchanged (전종목 chg_pct 부호 카운트) |
| sector | 업종명 26개 | chg_pct (시총가중 Σcap·chg/Σcap), value_krw (거래대금 합), n |

공통 컬럼 [as_of, trade_date, kind, key], kind별 값 컬럼 유니온(미해당 NaN).
섹터 매핑은 미러 `krx_sector.parquet`의 최신 date 스냅샷, 미분류 종목은 "기타".
**리셋 규칙**: 폴러가 기존 timeline의 trade_date≠오늘이면 버리고 새로 시작.
폴러는 단일 쓰기자(스케줄 직렬)라 동시성 문제 없음.

**정합성 불변식** (전부 이 스펙의 수용 기준):

1. 이 두 파일은 `app/` 밖으로 나가지 않는다 — 레이크·raw 체크포인트 무접촉.
2. 종목 등락률은 KRX 제공값만 쓴다 — 보관 종가로 자체 계산하지 않는다
   (당일 배당락·분할 시 우리 히스토리와 어긋나는 것이 정상이며, 그래서 금지).
3. 장중 값을 정산 가격 차트에 이어붙이지 않는다 — 별도 블록으로만 표시.
4. 백테스트·전략 추적·신호 빌더·brief는 이 파일을 읽지 않는다.
5. 야간 파이프라인(`drop_unsettled_today` 포함)은 무변경.

## 6. D3 — 서빙: `GET /intraday/market`

두 파일을 읽어 한 응답으로 조립한다 (내 종목 포함 — watchlist/holdings 저장소와
latest를 ticker 조인, 종목명은 기존 meta 조인):

```
{ active, is_open, as_of, trade_date,
  indices: [{name, level, chg_pct, sparkline: [{t, level}]}],
  breadth: {advancers, decliners, unchanged},
  sectors: [{name, chg_pct, value_krw, flow: [{t, chg_pct}]}],   // 26개 전부
  top_value: [{ticker, name, close, chg_pct, value}],            // TOP 10
  top_movers: {up: [...], down: [...]},                          // 각 TOP 10
  my: {watchlist: [...], holdings: [...]} }
```

- **급등락 필터**: 시총 ≥ 1,000억 & 당일 거래대금 ≥ 30억. 저유동성 잡음 배제.
  거래대금 TOP은 자체 정렬이 필터라 무조건.
- **모드**: `is_open` = KST 09:00~15:30 & 평일 & trade_date=오늘.
  마감 후에도 trade_date가 최근 거래일이면 `active:true`로 "마감 현황"을 계속
  서빙한다 (다음 거래일 첫 폴까지 유효한 최신 현황이므로).
- **강등**: 파일 부재·파싱 실패·trade_date가 최근 거래일보다 과거(2거래일 이상
  낡음)·장중인데 as_of 40분 초과 → `{active: false}`. **500 금지.** 클라이언트는
  active:false면 장중 UI를 전부 숨기고 현재와 동일하게 동작한다.

## 7. D4 — 화면

**인사이트 페이지 = 2탭**: `[🔴 장중 | 정산 인사이트]`. 새 페이지·새 내비 없음.

- 기본 탭: is_open이면 장중, 아니면 정산. active:false면 장중 탭 미노출.
- 장중 탭 블록 (위→아래):
  1. **지수 스트립** — KOSPI·KOSDAQ 현재가·등락률 + 당일 스파크라인(30분 해상도),
     브레드스 카운트(상승/하락/보합).
  2. **섹터 히트맵** — 26업종, 색=등락률, 타일 크기=거래대금.
  3. **섹터 흐름 차트** — 당일 시계열 라인, **거래대금 상위 8개 업종** 표시
     (돈의 흐름 우선. 전체 토글은 후속).
  4. **거래대금 TOP 10** / 5. **급등·급락 TOP 10** — 종목 행 클릭 시 상세 이동.
  6. **내 종목 장중 현황** — 관심·보유 통합, 등락률 정렬. **KR 종목만** 장중 값
     표시. US 종목은 이 블록에서 제외한다 (US 정산 현황은 기존 화면이 담당).
- 모든 장중 블록 헤더에 **"지연 시세 · HH:MM 기준"** 배지 (마감 후 "15:30 마감").
- **홈**: MarketTiles의 **KR 지수 타일만** active 시 장중 값(🔴 HH:MM)으로 갱신
  (US 타일은 정산 유지), Watchlist/Portfolio 카드의 **KR 종목 행에만** 장중
  등락률 칩 추가. 그 외 홈 무변경.
- 정산 탭: 기존 인사이트 섹션 그대로 이동, 무변경.
- 클라이언트 폴링: 장중 탭 표시 중에만 5분 간격 refetch (RTK Query).

## 8. D5 — 단계 0: US 종가 아침 반영

- EventBridge 룰 추가: **평일 09:00 KST EC2 기동** (기존 19:00 룰과 동일 대상)
  + 짝이 되는 **failsafe-stop 10:40 KST** (기존 20:40 룰과 동일 패턴, 100분).
- **파이프라인 코드 무변경**: KR 수집은 18시 가드·체크포인트로 자동 스킵되고,
  massive는 완결 캡으로 방금 끝난 US 세션(전일 ET)을 수집, build_insights가
  US 반영판을 재발행한다.
- 아침 텔레그램 브리핑도 그대로 발송된다 — **"US 마감 반영 아침판"으로 허용**
  (원치 않으면 후속에서 시간대 조건 추가).
