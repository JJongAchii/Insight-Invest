# ADR-0017: 읽기 요약 생성과 원문 대조 검수를 분리한다

- Date: 2026-09-08
- Status: 구현 / 실제 검수 정확성 인수 전, 운영 배포 전
- Scope: Research 읽기 피드. 전략 재현·성과 감사·새 검색 API 운영은 포함하지 않는다.

## 배경과 승인

v7 실제 AQR 요약은 인용 문자열이 원문에 있어도 금융 개념을 잘못 옮기고 서로 다른
지표의 조건을 섞었다. 문장 인용과 JSON 계약만으로 의미 정확성을 승인할 수 없다.
사용자는 다음 단계인 별도 원문 검수와 월 총 $2 내 시험 $0.50 / 운영 $1.50 재배분을
“응 진행해줘. 그리고 아래와 같이 검색 소스를 확장하는건 별로인가” 메시지로 승인했다.
기존 시험 예약 $0.08204045는 유지한다. 제안된 학술 검색 확장은 별도 설계 논의다.

## 결정

1. v7 생성 프롬프트·캐시 키는 유지한다. 이미 만든 요약을 다시 생성하지 않고 새
   `research_review` 요청에서 원문 최대 24,000자와 정확한 초안을 독립 입력으로 대조한다.
   모델은 동일한 승인 GPT-5 mini, medium reasoning이며 대화/response ID를 공유하지 않는다.
   이는 별도 호출이지 모델 계열이 독립인 외부 감사라는 뜻은 아니다.
2. 제목, 자료 유형, 관련성·실질성, 다섯 요약 항목, 추가 메모를 모두 검사한다. 각 항목은
   supported / unsupported / unclear / not_applicable을 반환한다. null 항목만 N/A가 된다.
   의미·수치·대상·조건·귀속·금융 용어를 점검하고 각 문장의 **붙어 있는 인용**으로
   주장을 지지하는지 확인한다. 원문 다른 곳의 사실로 부실한 인용을 합격시키지 않는다.
3. 최종 판정은 코드가 계산한다. 하나라도 unsupported/unclear이면 전체 요약을 보류한다.
   검수자가 초안을 고치거나 자동 생성-재검수를 반복하지 않는다. 연구 방법·성과 자체가
   옳다는 판정이나 백테스트 검증은 하지 않는다. 논문 형식/백테스트 없는 실무 글도 허용한다.
4. 검수 캐시는 별도 `research_analysis/reviews/`에 저장한다. 원문 digest, 제목, 파서·범위,
   생성 fingerprint, 정확한 초안 digest, 검수 모델·버전·설정을 키에 묶는다. 실제 입력 digest,
   대조 시각, 항목별 원문 인용, 이유, 사용량·비용을 기록한다. 변경된 초안은 통과증을 못 쓴다.
5. 한 정기 실행은 최대 한 번의 유료 단계만 처리한다. 생성 → 다음 실행에서 검수하므로
   정상적인 두 단계에도 수집 이후 추가 주기가 필요하다. 통과 검수 없는 옛 ready 캐시도
   핵심·알림에서는 제외한다. 한도가 부족하면 초안을 유지하고 다음 예산에 검수만 재개한다.
6. 의미 보류는 종결 결과다. 원문/서재 항목은 남기고 알림 outbox는 억제 처리한다.
   통신·계약 오류는 단계 fingerprint별 최대 세 번, 30분 간격으로 재시도하며 실패 예약을
   유지한다. 대기 중인 알림은 먼저 소비하지 않는다. 재생성/소스 변경 없이 자동 재채점하지 않는다.
7. 화면은 검수 통과 요약만 기본 표시한다. 대기·보류는 원문 제목·발췌와 상태를 보여준다.
   생성물은 캐시/분석 기록에 보존하고 원문, 읽음·저장·확인 상태는 삭제하거나 재설정하지 않는다.
   최초 핵심 가용 시각은 생성 시각이 아니라 검수 시각이며 기존 가용 시각은 보존한다.
8. 두 단계 모두 같은 월 예산 원장에 요청 전 예약한다. 시험 $0.50 / 운영 $1.50은 이
   Research의 UTC 월별 요청 한도이며 계정 전체 청구나 AWS 비용을 제한하는 것은 아니다.

## 인수

- 오프라인: 전체 항목 검사, 인용 ID 검증, 영수증/초안 변조, 캐시 복구, 단계 재시도,
  기존 예약 유지, ready 플래그 우회 차단, 서재 바이트 보존, 알림 대기/보류 처리.
- 실제: 보존된 v7 AQR·Robeco·CFM 세 초안에 검수만 적용한다. 기존 의미 오류를 검수자가
  실제로 찾는지 사람이 원문과 대조한다. 모든 항목 보류도 정상 API 계약 결과일 수 있으나,
  좋은 글을 과도하게 차단하는지와 실제 오류 누락은 별도 품질 실패로 기록한다.
- `api_contract_qualified`는 현재 초안의 검수가 모두 종결되었다는 연결/구조 판정이다.
  `ready`, `reviewed`, `review_rejected`를 분리하며, 이것을 사람의 의미 품질 승인으로 쓰지 않는다.
- 20–30편 다양성 인수와 운영 수집/알림 E2E 전에는 main/AWS/Vercel 릴리스 완료를 주장하지 않는다.

## 한계

같은 소형 모델의 생성·검수는 오류가 상관될 수 있다. 두 호출을 했다는 이유로 정확성을
보장하지 않는다. 24,000자 범위 밖의 내용, PDF 표/수식 파싱 손실, 인용 위치의 페이지
번호는 새로 해결된 문제가 아니다. 원문 접근과 범위 고지를 유지한다.

## 첫 실제 검수 실패와 v2 보완

Actions 34195893630 (`7e53de9`)은 기존 v7 세 초안을 다시 생성하지 않고 검수만 했다.
세 편 모두 supported로 반환되어 API 계약은 통과했지만, AQR의 영어 개념 오역과 지표
속성 혼합을 검수도 반복했다. 따라서 **검수 정확성 인수 실패**이며 이 결과로 배포하지 않는다.
세 검수 추정비는 $0.017808, 누적 시험 예약은 $0.09984845 / $0.50이다.

v2는 초안을 그대로 유지하며 검수 입력에 항목별 허용 근거 ID를 명시한다. 통과 판정에서
다른 항목/문서 위치의 근거를 가져오면 코드가 보류한다. 각 항목에 쓴 18xx–21xx 형태의
연도 리터럴이 해당 인용에 없거나, 추가 메모의 연도가 기존 요약 근거에 없으면 보류한다.
이는 제한적인 추적성 검사이지 모든 수치·의미의 정확성을 증명하는 검사가 아니다.
모델의 원래 status/reason은 유지하고 코드의 `guard_issues`를 별도로 기록한다.
따라서 모델은 supported라 했지만 최종 보류된 사례를 숨기지 않는다.

검수만 같은 mini의 high reasoning으로 조정하고, 대조 이유 → 근거 → 판정 순서로
응답을 받는다. 원문 주체/대상/조건과 금융 개념 대응을 반증하도록 요구한다. 생성은 v7/
medium 그대로이며, 상위 모델·다른 제공자로 전환하지 않는다. 요청 예약 상한도 동일하다.
먼저 AQR 한 편만 재검사하고 실제 오류 탐지/보류 이유를 읽은 뒤 후속 시험 여부를 정한다.

첫 v2 AQR 요청(Actions 34198353351)은 60초 HTTP ReadTimeout으로 검수 결과를 받지
못했다. 성공/의미 보류로 세지 않는다. 실패 예약 $0.030711을 유지하여 누적 예약은
$0.13055945가 되었고, 해당 fingerprint의 재시도 가능 시각 2026-09-08 07:45:14 UTC를
앞당기지 않는다. 요청을 다시 생성한 결과로 부르거나 이전 v1 pass를 빌리지 않는다.

검수 HTTP 한도를 120초, 정기 폴러 실행 한도를 300초로 맞춘다(10분 스케줄보다 짧음).
타임아웃 변경은 검수 의미 캐시 키를 바꾸지 않아 기존 실패의 대기/시도 수를 유지한다.
단계별 실패 receipt는 `research_analysis/retries/<fingerprint>.json`에도 저장한다.
격리 시험의 표본 교체 전에 기존 receipt를 이관하고, 다른 기관을 시험하거나 항목이
제거·재추가돼도 실패 횟수와 대기를 초기화하지 않는다. 기존 원장/캐시를 삭제하지 않는다.
API 서빙도 읽기 시점에 검수 버전을 확인하므로 다음 폴러 실행 전에 옛 core/배지가 노출되지 않는다.
