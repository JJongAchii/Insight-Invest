## 검증과 릴리스

고정 운영 27편을 7/7/7/6편으로 나눈 development regression에 모두 보존한다.
같은 발행처의 여러 글을 entry ID로 구분하며, 공식 원문 hash/title/ID 변경 또는 누락 시
대체 글로 바꾸지 않고 유료 호출 전에 멈춘다. 기존 직렬 GitHub Actions와 격리된
qualification prefix/누적 비용 원장을 그대로 사용한다. 이전 수동 core 판정으로
자동 분류 검증을 통과시키지 않는다.

오프라인 테스트는 계약 검증이며 실제 글의 품질 증거가 아니다. 실제 API 출력은 원문과
사람이 비교하고, 수정에 사용하지 않은 새 글도 별도로 확인한다. 자동화 기대 라우팅,
문장 근거, 정보성, 한국어 의미, 수치 조건을 따로 기록한다. 실패와 비용을 지우지 않는다.
캐시 게시·배포 전 실제 출력 검토가 필요하며, 기존 원문/읽음/저장/확인 상태는 보존한다.

참고: [OpenAI의 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices)가
권하는 작업별 표본과 사람의 대조 원칙을 기존 자체 qualification에 적용한다.
모델 API의 구조 적합성을 편집 품질이나 투자 성과 검증으로 부르지 않는다.
