## 검증과 릴리스

고정 운영 27편을 7/7/7/6편으로 나눈 development regression에 모두 보존한다.
같은 발행처의 여러 글을 entry ID로 구분하며, 공식 원문 hash/title/ID 변경 또는 누락 시
대체 글로 바꾸지 않고 유료 호출 전에 멈춘다. 기존 직렬 GitHub Actions와 격리된
qualification prefix/누적 비용 원장을 그대로 사용한다. 이전 수동 core 판정으로
자동 분류 검증을 통과시키지 않는다.

오프라인 테스트는 계약 검증이며 실제 글의 품질 증거가 아니다. 실제 API 출력은 원문과
사람이 비교하고, 수정에 사용하지 않은 새 글도 별도로 확인한다. 자동화 기대 라우팅,
문장 근거, 정보성, 한국어 의미, 수치 조건을 따로 기록한다. 실패와 비용을 지우지 않는다.
캐시 게시·배포 전 실제 출력 검토가 필요하며, 기존 원문/읽음/저장/확인 상태는 보존한다.

참고: [OpenAI의 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices)가
권하는 작업별 표본과 사람의 대조 원칙을 기존 자체 qualification에 적용한다.
모델 API의 구조 적합성을 편집 품질이나 투자 성과 검증으로 부르지 않는다.

## 첫 실제 출력 이후의 제한된 비교

혼동한 문장이 accepted였다. Gabaix 인터뷰는 첫 회의 소개 질문으로 문서 전체 목적을

GPT-5.4 mini의 **작성·검수만** 같은 고정 7편, 같은 프롬프트, 이미 저장된 원문 선정으로

[공식 가격](https://developers.openai.com/api/docs/models/gpt-5.4-mini)을 적용한다.
진단용 결과는 캐시 게시가 금지된다. 분류/경계·운영 기본 모델·기존 과금 원장은
바꾸지 않고 기존 qualification $4 한도에 포함한다. 새 모델의 한국어 품질은
문서 설명만으로 가정하지 않는다. 이 비교 중에는 프롬프트를 바꾸지 않는다.

## 비교 이후의 수정 후보

run 34935147915의 5.4 mini도 붙은 인용 밖의 지시문, 다른 가상 포트폴리오의 면책문,
직역을 남겼다. AQR의 적절히 좁힌 제목을 거절하면서 실제 조건 누락은 놓치기도 했다.
모델 변경만으로 품질이 해결됐다고 결론내리지 않는다. 두 비교는 실패 증거로 보존한다.

- 선정 v12는 소개 질문보다 전체 본문의 지속적인 설명을 먼저 읽는다. 핵심 구절 하나와
  필요할 때 그 방법만 고르고, 질문/결과/한계의 템플릿 채우기는 스키마에서 제거한다.
- 작성 v13은 경계 검수가 인정한 한 구절로 `why_read`에 핵심 내용 2–3문장을 쓴다.
  다른 네 항목은 null로 고정한다. 저자 주장과 그 조건은 보존하되 번역자가 투자 조언을
  덧붙이지 않는다. 이는 원문 전체/논문 재현 요약이 아니라 읽을 포인트를 전달하는 노트다.
- 검수 v10은 그 한 설명의 주체·인과·크기·조건을 대조한다. 원문 일부에 집중한 정확한
  제목은 허용하지만, 서로 다른 시험/포트폴리오의 한계를 합치는 것은 허용하지 않는다.
- 원문 선정·작성·검수에 고정 `gpt-5.4-2026-03-05`를 후보로 사용한다. 한 구절의
  경계 판정은 `gpt-5-mini`를 유지한다. 선택된 원문만 호출하며 예산·캐시를 그대로 쓴다.
  모델별 비용을 별도로 계산해 저렴한 진단 writer가 원문 선정 비용까지 낮추지 못하게 한다.
  [공식 가격](https://developers.openai.com/api/docs/models/gpt-5.4)은 입력/출력 1M당
  $2.50/$15.00이다. 예산 한도 자체를 늘리지 않으며 실제 처리량·비용을 보고한다.
- 현재 core 27편의 원문 대조에서 24편을 유지하고 3편을 context로 정정한다. CFM
  Systematic Global Macro의 과거 수동 core 판단도 전체 원문 재검토로 정정한다.

이 수정 후보의 실제 API/원문 대조가 끝나기 전까지 운영 반영·품질 완료를 주장하지 않는다.
