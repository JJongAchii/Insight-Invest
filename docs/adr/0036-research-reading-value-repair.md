# 0036 — 투자 설명과 상품 프로필을 구분하고 읽을 수 있는 요약을 검증한다

Date: 2026-09-15
Status: implementation under qualification; not a production quality acceptance

## 확인한 결함

운영 core 27편의 공식 원문을 2026-09-15에 다시 가져와 저장된 source digest와
전부 대조했다. 수집 실패가 아니라 선정·편집 문제였다. Robeco의 Circular Economy와
Credit income 글은 현재 포지셔닝·상품 장점을 설명하지만 새로 core로 승격됐다.
Credit income의 동일한 원문 구절을 경계 검수가 insight에서는 operational_detail,
method에서는 objective_or_profile로 모순되게 판정했는데 기존 OR가 승격시켰다.

반대로 Robeco Systematic fixed income에는 스프레드만으로 저평가를 판단하는 오류와
발행사 위험을 함께 비교하는 관점이 있다. 상업적 발행처라는 이유로 제외하면 안 된다.
기존 한국어 요약은 이런 구체적 설명보다 일반적인 장점·번역투·면책문을 전달했다.

## 결정

- 선정 v11: 현재 보유·기간·베타·우량기업 속성 나열과 실제 분석/비교/인과 설명을 구분한다.
  학술 형식, 공식, 백테스트를 필수로 만들지 않고 유용한 실무 글을 보존한다.
- 경계 v8: 같은 구절의 실질적 내용 판정이 상충하면 uncertain으로 보류한다.
  서로 다른 구절 중 하나의 유용한 설명만 있어도 통과할 수 있는 기존 원칙은 유지한다.
- 작성 v12 / 검수 v9: 한두 문장에 구체적인 투자 설명을 담고 일반적인 상품 장점,
  연구 한계와 무관한 면책문, 이해하기 어려운 번역투를 배제한다.
- 표시 v3: 검수된 구체적 why_read만으로도 유용한 노트를 만들 수 있다. 템플릿을
  채우려고 빈약한 finding을 강제하지 않는다. 기존 인용·수치·조건·원문 결합 검사는 유지한다.
- 기존 GPT-5 mini와 승인된 9월 $5 합산 예산을 유지한다. 새 모델/서비스를 추가하지 않는다.

## 검증과 릴리스

고정 운영 27편을 7/7/7/6편으로 나눈 development regression에 모두 보존한다.
같은 발행처의 여러 글을 entry ID로 구분하며, 공식 원문 hash/title/ID 변경 또는 누락 시
대체 글로 바꾸지 않고 유료 호출 전에 멈춘다. 기존 직렬 GitHub Actions와 격리된
qualification prefix/누적 비용 원장을 그대로 사용한다. 이전 수동 core 판정으로
자동 분류 검증을 통과시키지 않는다.

오프라인 테스트는 계약 검증이며 실제 글의 품질 증거가 아니다. 실제 API 출력은 원문과
사람이 비교하고, 수정에 사용하지 않은 새 글도 별도로 확인한다. 자동화 기대 라우팅,
문장 근거, 정보성, 한국어 의미, 수치 조건을 따로 기록한다. 실패와 비용을 지우지 않는다.
캐시 게시·배포 전 실제 출력 검토가 필요하며, 기존 원문/읽음/저장/확인 상태는 보존한다.

참고: [OpenAI의 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices)가
권하는 작업별 표본과 사람의 대조 원칙을 기존 자체 qualification에 적용한다.
모델 API의 구조 적합성을 편집 품질이나 투자 성과 검증으로 부르지 않는다.
