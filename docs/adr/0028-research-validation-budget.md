# ADR-0028: 현재 월 한도 안에서 실제 원문 검증에 예산 재배분

- 날짜: 2026-09-14.
- 사용자 승인: `그래 지금 검증하는 과정에서는 제대로 설계되기 전까지 예산을 다
  사용해도되. 필요하면 더 늘려줄게. 제대로만 만들어줘`.
- qws intent `2d79bae58179` 유지. 예산 승인이지 의미 인수 생략 승인이 아니다.

## 비용 배분

승인된 현재 월 총액 $2 안에서 운영 $1.00 + 격리 검증 $1.00으로 바꾼다.
관측 원장은 운영 $0.846975, 검증 $0.58130420이며 두 새 한도보다 작다.
검증은 약 $0.419의 여유로 현재 v3를 실제 실행한다. 필요하면 사용액을 확인해
월 $2 안의 배분을 더 조정할 수 있지만, $2 자체를 넘어가는 추가 증액은 먼저 묻는다.
원장 초기화·실패 예약 환불·입출력 축소·소스 치환으로 한도를 우회하지 않는다.

`insight-invest-research-poller`의 비용 환경변수 한 개만 revision 조건으로 변경한다.
API 키 등 나머지 환경변수는 메모리에서 그대로 전달하고 출력·파일에 저장하지 않는다.
코드 이미지, 스케줄, 분석 스위치, feed/서재/알림·비용 원장은 바꾸지 않는다.
CloudFormation 템플릿·기본값·시험 환경 한도·실제 운영 한도 확인을 모두 $1.00으로
일치시킨다. 현재 main의 이전 템플릿이 재배포돼 한도가 달라지면 시험 workflow는
시작 전 실제 운영 설정 검사에서 중단한다. 이 PR의 분류 코드는 아직 배포하지 않는다.

## 검증 순서와 정지 기준

1. 이미 커밋한 v3 설명 카드 요청, v7 선별, GPT-5 mini, medium, 입력/출력 한도를
   그대로 유지한 채 고정 AQR/SaaS 경계 표본을 실행한다.
2. 통과 시 기존 제품·실무·방법·주제 표본과 별도 확장 2편을 검사한다. 원래 13편과
   확장 2편의 결과를 구분하고, 기존 실패를 덮지 않는다.
3. 자동 라우팅 기대값뿐 아니라 설명 카드·인용·판정의 의미가 맞는지 원문과 대조한다.
   그 이후에만 본문 요약·UI·사용자 상태 보존 및 운영 반영을 검토한다.

현재 버전 실패 시 동일 요청을 유리한 응답이 나올 때까지 반복하지 않는다. 실패의
구체적 근거를 보존한 뒤 별도 수리 가설·범위를 정해야 한다. 예산을 쓸 수 있다는
승인이 모델 교체, 임의 분류 기준 변경 또는 실패 표본 삭제를 자동 허용하지 않는다.
