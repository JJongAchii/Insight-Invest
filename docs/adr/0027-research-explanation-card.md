# ADR-0027: 판정 앞에 원문의 실제 설명을 추출

- 날짜: 2026-09-14.
- 승인: 원인 설명과 설명 근거 중심 수리 제안에 대한 `그래 한번 해보ㅓㅏ`.
- qws intent `2d79bae58179` 유지.
- 상태: 구현·오프라인 검사 완료. 실제 API 의미 인수는 예산 승인 대기, 운영 배포 전.

## 실패에서 확인한 것

ADR-0025/0026의 SaaS 오분류는 원문에 없는 인용이나 전송 오류가 아니다. 실제
투자자용 프레임워크 선언과 기업 매출/제품 위험 설명을 투자 측정으로 잘못 읽었다.
v2에서 분석 대상 enum을 추가해도 그 enum부터 잘못 골랐다. 같은 모델의 요청 두 개는
독립적인 오류 검증이 아니다. 본문 분절 영향과 모델 간 차이는 분리 검증되지 않았다.

## 수리 범위

기존 source-only 2차 요청을 `reading-boundary-v3-explanation-card`로 바꾼다.
첫 v7 선별, 모델 GPT-5 mini, medium, 4096 출력 한도, 24000자 원문 입력,
요약·대조 단계 수, 파서·수집 소스·발행 경로·기존 캐시는 바꾸지 않는다.

같은 요청 안에서 아래 사실 설명을 **먼저 출력**하고 그 뒤에 분석 대상과 기여를
판단한다. 새로운 독립 에이전트나 세 번째 유료 요청을 추가하는 것은 아니다.

1. object: 실제로 연구한 양·규칙·관계·시스템.
2. work: 본문이 설명한 입력/변화→절차·비교·인과관계. 방법의 존재·목표 선언은 제외.
3. result: 그 절차·비교·관계가 설명하거나 산출한 내용. 정성적 함의·측정 함정도 허용.

각 항목은 간결한 설명과 별도 원문 문장 ID를 갖고, 본문에 없으면 null이다. 기업
매출·제품 경쟁을 투자 용어로 재포장하지 않고 그대로 추출한다. 사업 분석도 세 항목이
모두 있을 수 있으므로 **완전성과 퀀트 적합성은 별개**다. 수식·백테스트·성과 숫자를
필수로 만들지 않는다. 기존 비투자 대상 veto는 유지하고, substantive여도 설명 항목이
하나라도 null이면 코드가 uncertain/held로 둔다. 관련 글의 원문·열람·검색·저장은 유지한다.

세 설명의 인용과 statement를 원문 digest·입력 digest·판정 digest에 함께 묶는다.
캐시 발행 경로도 모든 설명 인용을 원문에서 다시 확인한다. v1/v2 캐시를 v3 통과로
인정하지 않는다. **인용 존재와 설명 완전성의 코드 검사는 의미적 지지를 보장하지 않는다.**
실제 출력에서 각 설명이 인용으로 뒷받침되는지와 최종 분류가 맞는지를 따로 읽어야 한다.

## 고정 검증

기존 13편의 기대값·본문 hash·실패 결과를 보존한다. 우선 SaaS(context/held)와
AQR Warming World(core)를 같은 v3 정책으로 확인한다. 이후 기존 표본과 실무 퀀트
양성을 대조한다. 한쪽만 막거나 모든 글을 보류하는 것은 성공이 아니다.

13편 밖의 추가 비교 묶음 `reading-gate-extension-v1`을 v3 API 실행 전에 고정한다.
전체 캐시 본문을 읽은 D. E. Shaw Concentration Game(core)와 Robeco From AI Copilots
(context)다. 전자는 포트폴리오 위험 기여·롱온리 제약·초과수익 breadth를 설명하고,
후자는 AI 운영 책임·로그·권한·검토 절차를 설명한다. 기존 사람 원문 감사에는 등장한
글들이므로 오염 없는 신규 holdout 또는 미관측 전체 피드의 일반화 검증으로 부르지 않는다.

수리안 작성 중 CFM Systematic Global Macro 인터뷰도 읽었다. 상품·운용 소개와
직교 위험 모드 설명이 섞여 있어 새 이진 정답으로 확정하지 않았다. API 결과를 보고
제외한 것은 아니며 운영 소스/항목에서 삭제하거나 주제 차단 규칙에 넣지 않는다.

오프라인 synthetic 응답 테스트는 상태·인용·캐시·알림 계약만 검사한다. 이 결과를
모델이 원문을 올바르게 읽었다는 증거로 보고하지 않는다. 의미 인수 실패 시 원문·출력·
비용을 보존하고 추가 유료 버전을 자동 반복하지 않는다. 전체 배포 인수 전 PR51은 draft다.

## 비용 경계

시작 검증 원장 $0.58130420/$0.60, 남은 $0.01869580. 현재 v3 요청의 보수적 사전
예약은 AQR $0.019035, SaaS $0.01906950으로, 실제 과금이 아니라 출력 최댓값과
입력 바이트 상한을 포함한 예약이다. 현재 한도로 두 요청 모두 시작할 수 없다.
원문을 줄이거나 출력 한도를 낮춰 이 경계를 우회하지 않는다.

월 합계 $2 유지하에 운영 $1.40→$1.30, 검증 $0.60→$0.70 재배분 승인을 다시
비동기 질문으로 요청했다. 명시 응답 전에는 예산 설정·원장·운영 환경을 바꾸지 않으며
유료 요청을 하지 않는다. 승인 시에도 실제 운영 사용액·환경을 먼저 확인하고 양쪽
한도를 일관되게 반영해야 한다. 예산 부족은 의미 검증 실패나 성공과 별도로 기록한다.

OpenAI Docs의 structured output 계약을 적용하지만 그 자체를 내용의 정확도 보장으로
해석하지 않는다. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini).

## 이번 실행 기록

연구·알림 회귀 테스트 304개와 Ruff, Next.js production build가 통과했다.
예고한 4편을 공식 URL에서 다시 가져와 제목·전체 본문 digest를 고정값과 확인했다.
새 설명 요청의 입력 digest와 예약액도 실제 파서 출력으로 계산했다. 이 검사는
LLM 호출 0회이며 의미 인수는 `not_run`이다. 새 분류가 맞는지는 아직 모른다.
기존 13편의 객체는 수정하지 않고 비교용 2편만 별도로 추가했다.

예산 재배분 명시 응답이 없어 유료 호출·예산 설정 변경·운영 이관은 수행하지 않았다.
PR #51 draft/HOLD를 유지한다. 이전 v1/v2 실패와 이번 미실행을 구분해서 보존한다.
